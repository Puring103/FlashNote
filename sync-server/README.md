# 自建同步服务运维

在包含 `compose.yaml` 的 `sync-server/` 目录执行以下命令。用同一个 Docker Compose 项目名管理这个实例。默认项目名是 `suojian`。首次部署见[项目 README](../README.md#自建同步服务器)。

## 注册与密钥策略

在 `.env` 中设置 `SUOJIAN_REGISTRATION=false`（默认）可关闭自助注册。管理员仍可在 Casdoor 创建账号。设为 `true` 后，使用同步域名下的 `/signup/suojian` 注册，再在客户端登录。注册网页只建立身份；12 个英文助记词由第一个登录并建立端到端资料库的原生客户端生成。

`SUOJIAN_E2EE=true`（默认）让新库采用端到端加密。设为 `false` 时，新库使用服务器托管密钥。该策略在每个库创建时固化：已有托管库继续使用原密钥，已有端到端库始终拒绝取钥接口。客户端登录托管库时需明确允许管理员解密。更改开关时先停止当前 Compose 服务，再从同一目录运行 `docker compose up -d --build --force-recreate`，使初始化程序更新 Casdoor 应用策略并让代理加载新配置；保留原数据卷。

端到端库的新设备需要原来的助记词。备份服务数据库可以恢复密文，无法代替用户保管助记词。CLI 可通过 `SUOJIAN_SYNC_WORDS` 读取原有助记词，显式运行 `suojian-sync recovery-words` 会把词输出到当前终端。仅在私有终端查看。托管库的 CLI 登录需显式设置 `SUOJIAN_ALLOW_MANAGED=true`。

## 确认服务就绪

```sh
docker compose ps
curl --fail --show-error https://你的同步域名/health
curl --fail --show-error https://你的同步域名/auth/config
```

在独立测试账号的 Windows 和 Android 客户端上用同一个 HTTPS 地址登录。先在 Windows 新建一张带附件的便签，在 Android 打开后核对正文和附件。两端断网后编辑同一段正文，恢复网络后核对冲突副本，两端选定并同步后应得到相同结果。再在一端移入回收站，确认另一端可以看到并恢复。测试账号至少要保留一张带附件的便签，供恢复验收使用。

## 服务端安全核查（2026-11-26）

| 核查项 | 当前结果与边界 |
| --- | --- |
| 公开入口 | Compose 仅将 Caddy 的 80/443 暴露到公网，Casdoor 和同步 API 的直连端口绑定回环。代理提供 HTTPS 与 HSTS，默认关闭自助注册页面和注册 API。修改设置后可在 `/auth/config` 核对 `registration_enabled` 和 `new_vault_encryption`。实际防火墙、DNS、证书和管理员权限需在对应实例核对。 |
| 身份与库隔离 | 数据路由校验访问令牌、issuer、应用、过期时间和资料库归属。令牌仅用于账户授权。端到端库不创建托管密钥记录，旧取钥接口拒绝访问，关闭实例的端到端默认策略也不会降级已有库。 |
| 密钥与恢复 | 助记词只在原生客户端显示和输入，服务器只接收校验指纹。取得服务器备份、重置密码均无法推导已有端到端库密钥。持有助记词和对应密文者具备解密能力，桌面系统剪贴板历史可能保留用户主动复制的内容。 |
| 并发与资源占用 | 服务端限制同时处理请求的工作线程数，套接字设有超时。附件 HEAD 请求只查询长度。每个对象、附件和资料库都有限额；累计账号数、SQLite 回执和备份的总磁盘占用仍需监控。开放注册会扩大资源消耗面。 |
| 完整性与可用性 | 对象及附件有客户端认证加密。服务管理员仍可观察元数据、停止服务、删除密文或恢复旧备份。从 0.12.0 起，客户端会校验已记录的同步检查点，并在检查点失效时重新核对数据。受控制的终端仍可能泄露明文。 |

核查使用本机 HTTP 服务与测试身份提供方。上线验收应使用独立测试账号，分别用原设备、只有登录密码的新设备和输入正确助记词的新设备验证结果。对已有托管资料库，升级后仍按托管库管理。本版没有就地换钥迁移；若要迁移，可在可信客户端导出明文 ZIP，导入独立的新端到端资料库并验证各设备，原托管库和旧备份仍可由旧密钥解密。

## 备份

```sh
mkdir -p "$HOME/flashnote-backups"
sh data-backup.sh backup "$HOME/flashnote-backups/flashnote-$(date +%F-%H%M%S).tar.gz"
```

备份期间会短暂停止服务。脚本结束时会重新启动原先运行的服务。归档包含 `.env`、Casdoor 的配置与数据库、同步数据库与附件、Caddy 的状态与证书。归档内含账号配置、托管模式的服务端密钥（如有）和证书私钥，请在访问受限的存储中加密保存，并另存一份到服务器之外。把对应的代码提交或发行标签和归档放在一起记录。升级或恢复期间避免同时执行其他 Compose 运维操作。

## 恢复或迁移到另一台服务器

1. 准备使用备份时相同版本部署文件的全新目录。使原 HTTPS 地址指向新服务器。登录标识绑定原地址，因此迁移时要保留 `SUOJIAN_ORIGIN`。恢复验收可仅通过测试客户端的名称解析将请求指向恢复实例，生产 DNS 可以继续指向原服务器。
2. 用一个新的 Compose 项目名，从可信的备份归档恢复。脚本要求目标目录中没有 `.env`、`.casdoor`，项目名下没有现有容器或卷。

   ```sh
   export COMPOSE_PROJECT_NAME=flashnote-recovered
   sh data-backup.sh restore /绝对路径/flashnote.tar.gz
   docker compose up -d --build
   ```

3. 先检查 `/health` 和 `/auth/config`。再用原测试账号在空白客户端资料库登录，同步并核对原便签、附件、分组和回收站状态。用第二个空白资料库同步一次新修改，确认恢复实例可以继续接收变更。

同一台服务器的标准端口只允许一个实例占用。切换前先停旧实例，保留它的目录与数据卷。若恢复中途失败，用另一份全新目录和新的项目名重试。

**从较旧备份回档时，用已有资料库的设备验收。** 先保留各设备的资料及备份之后的编辑。客户端和同步服务均运行 0.12.0 或更新版本时，客户端发现已记录的同步检查点失效后，会从头接收云端对象并重新核对本机修订。用一台已有同步记录的设备接收恢复实例中新建的便签，再从另一台设备核对备份后仍保存在原设备上的便签。出现差异时暂停切换，保留原资料库供核对和导出。升级前版本的回档风险见[历史审查记录](../docs/架构审查-2026-11-25.md)。

## 升级与回退

1. 先按上面的流程备份，记下旧版提交。暂停各设备同步，把新版部署文件放到原目录，保留 `.env`、`.casdoor` 和 Compose 项目名。
2. 运行 `docker compose up -d --build` 并检查服务就绪。将所有同步设备升级到与服务兼容的版本后恢复同步，验证登录、双端便签和附件同步。新版客户端使用新版服务提供的同步检查接口，旧版客户端无法读取新版压缩附件。
3. 需要回退且新版本已写入数据时，使用旧版部署文件和升级前的备份恢复到新项目。安排切换前先导出升级后新增的便签，再导入恢复实例。
