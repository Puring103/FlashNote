# 未来网页版接入策略

更新：2026-11-13。后端提供独立的分页浏览、按 ID 读取密文对象和附件下载能力。网页不需要完整同步后才能显示；本次仍不实现网页界面，也不引入多人协作、实时共编或新同步协议。

## 界面与数据复用

当前瀑布流、分类、便签编辑、回收站、冲突选择的交互可以用于网页。GPUI 窗口和渲染代码不能直接变成网页，未来需另写 Web 界面；桌面多窗口、托盘、全局快捷键与系统文件路径改为浏览器内的对应交互。

`Note`、`Group`、带稳定 ID 的内容块和附件引用都是 JSON 数据，与 GPUI 控件无关。桌面与网页继续使用相同的对象 ID、版本、密文信封和附件格式。浏览器作为用户自己的另一台设备，生成独立 UUIDv4，使用现有基础版本检查、离线合并与冲突选择。

编辑器 crate 已将文档/位置映射与可选 `gpui-view` 分开，可作为以后复用的基础。目前完整客户端仍依赖 Windows DPAPI、SQLite、文件系统和阻塞 HTTP，不能直接编译成可用的浏览器客户端。等实现网页版时再抽取与平台无关的数据模型、加解密、版本检查与合并核心，替换存储、网络和界面适配，不在本次提前拆分整个工程。

## 后端直接读取能力

下表均为已实现的接口。每次请求携带 Casdoor 访问令牌 `Authorization: Bearer <token>`，服务按资料库 ID 校验账号归属。客户端解密读取到的内容。 [同步认证](项目目录与安装.md#同步认证)

| 需求 | 接口 | 返回或行为 |
|---|---|---|
| 首屏及滚动加载便签 | `GET /v1/{vault}/objects?kind=note&limit=20` | 只返回一页便签密文和 `next_cursor`，不下载附件、不要求完整同步 |
| 按页获取分类 | `GET /v1/{vault}/objects?kind=group&limit=20` | 同一分页协议；省略 `kind` 时获取两类对象 |
| 需要完整离线副本时增量同步 | `GET /v1/{vault}/changes?after={cursor}` | 返回密文对象、同步游标及 `more`；与网页分页浏览独立 |
| 按 ID 读取一张便签或一个分类 | `GET /v1/{vault}/objects/{id}` | 最新的 `{header,ciphertext}`，与增量接口的条目格式一致 |
| 查询单个对象是否存在及响应长度 | `HEAD /v1/{vault}/objects/{id}` | 无响应正文，沿用鉴权及存在性检查 |
| 获取图片、音频或普通附件 | `GET /v1/{vault}/assets/{id}` | 加密二进制；浏览器解密后显示、播放或下载 |
| 查询附件是否存在及密文长度 | `HEAD /v1/{vault}/assets/{id}` | 无响应正文 |
| 保存便签、分类和回收状态 | `PUT /v1/{vault}/objects/{id}` | 密文信封；基础版本不符时返回 409 及当前云端版本 |
| 上传附件 | `PUT /v1/{vault}/assets/{id}` | 先上传密文附件，再提交引用它的对象 |
| 查看空间 | `GET /v1/{vault}/usage` | 密文字节数、容量上限、对象数与附件数 |

直接读取对象不会确认本地待上传操作，也不会推进客户端增量游标。对象不存在或不属于当前库返回 404；令牌无效返回 401。读取接口不返回本机历史版本；当前云端保存最新对象，回收状态在对象密文中。对象与附件的响应均为 `Cache-Control: no-store`。

分类名称、正文、文件名、图片与录音不提供服务端明文接口。随机 ID、类型、版本、附件引用、大小和访问时序属于服务端可见元数据。检索、分类筛选、冲突比较在客户端解密后的数据上完成。

## 分页浏览约定

首屏请求 `GET /v1/{vault}/objects?kind=note&limit=20`，解密这一页即可显示。只有滚动需要更多内容时，才使用 `GET /v1/{vault}/objects?kind=note&limit=20&cursor=<next_cursor>` 取下一页。游标应做 URL 编码，继续请求保留相同的 `kind`。接口返回 `items`、`next_cursor`、`more` 和 `snapshot`；最后一页的 `next_cursor` 为 null，`more` 为 false。

- 默认每页最多 20 条，`limit` 可设为 1～50，页面可以少于这个数量。
- 每页密文信封合计以 256 KiB 为目标上限。若首条便签本身超过该大小，则单独返回这一条，避免无法继续分页；单对象仍受现有 8 MiB 上传限制。这是按便签分页，尚未拆分单条正文或建立加密摘要。
- 按服务端接收对象更新的顺序倒序排列，使用基于序号的游标，不使用 offset。它不等同于客户端创建时间排序。
- 分页过程中若有便签或分类更新，旧游标返回 409，客户端保留已经显示的内容，刷新第一页并按对象 ID 替换/合并缓存；避免在变化的结果集中静默漏项。重复提交已接收版本不改变分页水位。
- 浏览游标与同步游标互不替代。加载一页不代表已完整同步，不能据此清除待上传内容、推进 `/changes` 游标，或把未加载的便签当作已删除。
- 请求包含鉴权和库隔离；游标绑定库及对象类型，跨库或更换类型复用返回 400。游标不是访问凭据。

当前 `kind` 只区分便签与分类。分类归属、回收状态、业务时间仍在密文中，服务端不能据此做全库筛选；客户端只能筛选已加载的页，也不能把当前页的检索结果宣称为全库搜索。未来网页若需要全库分类/回收站筛选和创建时间排序，再增加客户端生成的不含名称或正文的路由索引，并明确新增的元数据可见范围，不回退为先下载全部便签。

如果长便签导致首屏仍偏重，下一步由客户端生成单独加密的短摘要和预览引用，列表只取摘要，点开后才取完整正文；摘要与正文需要绑定相同对象及版本，并在保存时一并更新。服务端不能从现有正文密文截取摘要，本次未增加摘要上传格式。

## 浏览器读取与保存流程

1. 网页端的 Casdoor 登录和浏览器密钥保管仍待实现。当前客户端以账号会话调用 `POST /v1/account/key` 获取资料库 ID 和同步密钥。
2. 只取便签第一页，认证解密后立即显示；分类也可独立分页加载，滚动再取更多。已知对象 ID 时可直接读取最新对象。不会先循环 `/changes` 把全库取完再显示；接收时仍执行身份、版本、内容及附件引用校验，不能绕过本地待上传内容与冲突处理。
3. 只有可见图片、打开录音或下载文件时，才用附件 ID 获取密文，在浏览器本地认证解密，再生成临时 Blob URL。正文可以先显示，附件按需加载；使用结束后释放 URL，下载文件名来自解密后的便签。
4. 若以后支持网页离线编辑，用 IndexedDB/OPFS 实现本地对象、附件缓存、同步基线和待上传队列。桌面继续使用 SQLite。浏览器存储可能被清理，不把浏览器缓存当成唯一备份。
5. 编辑后先在客户端加密，再沿用当前 PUT、CAS 和冲突流程上传。附件按需读取是未来网页策略；桌面当前仍完整下载附件，服务端暂不支持 Range 或分块上传。

网页实现时需验证浏览器加密库与现有密文格式的互通，使用桌面生成的固定样例做双向验证。

## 部署与平台差异

未来优先让网页静态资源与 API 通过 HTTPS 同源部署，例如同一域名由反向代理分别提供静态页面和 `/v1/`。当前后端没有开放 CORS/OPTIONS；不为尚未实现的网页开放任意跨域访问。若确需不同域名，再增加明确的来源白名单、预检与浏览器会话策略。

粘贴本地图片、选择文件、麦克风录音可使用浏览器对应 API。任意远程图片的自动下载还受来源站点 CORS 限制，不能照搬桌面行为；受限来源可在桌面导入后同步，或由用户选择本地文件，不让同步服务代理下载明文图片。whisper.cpp 本地程序路径也不适用于浏览器，网页语音转写能力届时另定。

当前服务端托管账号同步密钥，能够解密数据。托管网页还需要信任服务商分发的 JavaScript。 [同步架构](项目目录与安装.md#当前架构)

## 本次范围

保留现有 JSON、加密与同步格式；提供 `GET objects` 分页浏览和 `GET/HEAD objects/{id}` 单对象读取，复用现有附件、增量和容量接口。已验证部分获取、分页顺序、类型筛选、字节预算、变化后重载、鉴权及库隔离，读取不改变容量与同步状态。网页 UI、加密摘要索引、浏览器密钥保管、离线存储和按需附件缓存均留待网页版实施时完成。
