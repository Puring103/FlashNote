# 同步与数据管理综合修改方案

2026-11-26 · 开发阶段

本方案覆盖核心数据模型、加密与恢复、多设备同步、服务端安全及登录前后的便签归属。开发期间采用当前数据格式，旧数据由开发者按需手动迁移。版本兼容和自动迁移均不列入本期任务。

## 核心代码与内容组织

桌面、Android 和 CLI 共用 Rust 核心，由 Store 统一保存对象、修订及待传状态。便签和分组保存在 SQLite；正文由有序的 Markdown、图片、音频和文件块组成。块 ID 标识正文节点，附件 ID 指向本机原件。编辑、搜索和查看历史都可离线完成。本机便签和附件允许明文保存。

同步沿用「准备、传输、提交」流程。客户端先传附件，再按云端基础修订提交对象。收到远端更新后，根据共同基线合并双方修改，无法合并的便签保留冲突副本。每页的对象和游标一起提交，网络请求期间的本地编辑留待下一轮上传。[核心架构与代码入口](核心架构与同步设计.md)

## 加密、恢复与服务端策略

| 决策 | 产品行为 |
| --- | --- |
| 默认关闭公开注册 | 管理员可通过 `SUOJIAN_REGISTRATION` 开关自助注册。注册建立账号身份，首次在客户端创建资料库时才生成助记词。 |
| 新库默认端到端加密 | 客户端先加密便签、分组和附件，再上传。服务器保存密文、同步所需的元数据和密钥校验指纹。助记词与解密密钥留在用户设备上。 |
| 12 个随机英文助记词 | 首台设备生成并提示备份。已授权设备可在设置中查看、复制。新设备登录已有账号后输入原词，验证通过才解密。失去全部已授权设备和助记词后，云端内容无法恢复。 |
| 可选托管模式 | 管理员可通过 `SUOJIAN_E2EE` 调整新库的默认模式。启用托管时，客户端明示服务器具备解密能力。已建立的端到端库保持原有密钥策略。 |

以上策略已有桌面、Android 和服务端实现，双设备恢复经过本机测试。真实部署仍需验证公开注册入口、HTTPS 证书、端口和账号隔离。端到端模式的验收标准是服务管理员即使持有完整备份并重置账号密码，也无法凭这些材料解密已有便签。服务器仍可观察对象标识、大小和同步时间。[服务端安全核查及运维说明](../sync-server/README.md)

## 多设备同步的修复优先级

0.11.0 使用修订回执校验游标，回档后重新核对对象；上传失败对象保持待传并继续拉取。离线新增便签若引用已删除分组，统一移入默认组。三项行为均有双端集成测试。[复现记录](架构审查-2026-11-25.md)

| 优先级 | 修改 | 验收场景 |
| --- | --- | --- |
| P1 | 让增量游标能识别服务端回档。恢复旧备份后重新核对两端对象，并保留仅存于旧设备的修订。 | 恢复备份后，用新设备新增便签。旧设备能发现回档、收到新便签，备份后产生的本地编辑也可找回。 |
| P1 | 分开记录上传失败和下载进度，失败对象继续保持待传。 | B 因配额不足上传失败时，仍能接收 A 的新便签。释放空间后 B 的原修改只上传一次。 |
| P2 | 明确删除分组后迟到便签的归属，让各端按同一规则持久化结果。 | A 删除分组，B 离线向该组新增便签。同步后所有设备都能在有效分组里找到该便签。 |

## 登录状态与本地便签

未登录时，只显示无账号归属的本地便签。登录后，只显示当前账号的数据。断网期间保留当前登录身份，账号内的新编辑仍归该账号。

首次登录且有本地便签时，可选择导入或跳过。跳过后，本地便签保持原样，退出账号时再次可见。有可导入内容时，账号设置提供「导入本地便签」。导入成功后，便签及其关联内容归入当前账号，后续同步重试不会再生成一份。桌面、Android 与 CLI 共用资料库归属逻辑，界面随登录状态自动显示对应内容。

## 界面文案

首次导入只需询问「将本地便签导入当前账号？」并提供「导入」「暂不导入」。账号设置使用「导入本地便签」「查看助记词」等动作名称。备份助记词时才说明云端加密、新设备需要原词以及遗失后果。架构说明、实现取舍和恢复流程保留在设计与运维文档中。
