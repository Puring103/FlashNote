# 项目目录与安装

## 代码归属

| 目录 | 用途 |
| --- | --- |
| `apps/desktop/src/` | Windows 界面、录音、托盘、快捷键与系统集成 |
| `apps/android/` | Android Kotlin / Compose 工程 |
| `crates/flashnote-core/` | 共享模型、存储、加密、同步、认证与备份 |
| `crates/flashnote-android/` | Android JNI 边界 |
| `crates/gpui-note-editor/` | 文档模型与桌面编辑器 |
| `crates/gpui/`、`crates/gpui-component/` | 带本地补丁的第三方桌面依赖 |
| `sync-server/` | 同步服务、认证代理、测试和 Docker Compose 部署 |
| `scripts/` | Windows 安装、打包与卸载，Android 构建和语音资源下载 |
| `tests/` | Rust 集成测试 |
| `assets/`、`design/`、`docs/` | 应用素材、设计参考和文档 |
| `runtime/`、`target/` | 不提交的本机运行资源、安装包和编译产物 |

根 Cargo.toml 保留桌面包入口，所以在项目根目录运行原有 Cargo 命令即可。新增跨平台业务应放入核心 crate；系统接口和界面放到对应 apps 目录。

## 当前架构

Windows 通过 Rust 直接调用 `suojian-core`，Android 通过 Kotlin → JNI → `suojian-core`。共享核心负责对象模型、SQLite、修订、附件、备份和同步。编辑器的文档模型由核心引用，GPUI 编辑器视图由桌面端启用。

本地提交由 Store 更新当前对象、修订和 outbox。同步按 prepare、transfer、apply 三阶段处理，桌面把网络传输放到后台，应用同步结果时提交对象和游标。Python 服务存储密文对象与附件，并代理 Casdoor 认证。当前服务端托管同步密钥，能够解锁数据。

### 同步认证

同步服务代理 `POST /auth/login`、`/auth/refresh` 和 `/auth/logout`。`GET /auth/config` 提供 Casdoor issuer、client ID 和登录方式。`/v1/*` 每次请求都经 Casdoor 验证访问令牌及其应用归属。Casdoor 不可用时返回 503。后台管理员通过 Casdoor 的 `/login` 管理 `noteharbor` 组织账号，初始管理员密码保存在 `.casdoor/casdoor-runtime/admin-password`。

### 模块边界与处理规则

| 模块 | 当前规则 |
| --- | --- |
| 桌面编辑 | 每个编辑器独立维护保存状态与所见版本。同步可以继续接收远端变更，保存时按所见版本合并。关闭窗口或主动退出前尝试保存，遇到组字或保存冲突时保留编辑器。 |
| Store | SQLite 连接限于共享核心。保存、导入和冲突决策共用本地修订写入，远端应用共用对象更新规则。历史查询按对象和时间建立索引。 |
| 同步 | 每页对象、修订和游标一起提交，内存只替换本页变更的对象。后续页失败时可从最近已提交的游标继续。 |
| Android | 工作线程复用资料库连接，常用修改只返回受影响便签。构建按请求的 ABI 打包，默认使用固定的 NDK 版本。 |
| 历史与附件 | 当前对象、回收站、仍保留的修订及同步基础版本所引用的附件会保留。当前便签的 `media_archive` 为编辑撤销恢复保留附件。清理未引用附件时同时回收原始文件和同步密文缓存。 |
| 提交检查 | GitHub Actions 配置了 Windows 上的 Rust、Python 和 Android 构建及测试。线上 Casdoor 测试需要独立测试账号。 |

桌面页面仍集中在 `ui.rs`，首次打开和 Android 手动同步仍会装载完整列表，上传阶段仍一次准备所有待传对象。两套 GPUI 本地补丁的升级需要核对补丁说明并验收窗口动画、托盘和菜单。

## Windows 安装

运行 `scripts/package.ps1` 构建完整 ZIP 安装包；已构建的版本可以使用 `-SkipBuild`。
产物位于 `runtime/packages/`。解压后双击“安装或更新.cmd”，首次安装默认使用 `%LOCALAPPDATA%\Programs\FlashNote`，升级沿用原安装目录。

安装后从开始菜单打开“索笺”；Windows 设置的“已安装的应用”中也会出现索笺，可从那里卸载。升级前从设置或托盘退出程序，然后运行新版安装包。

首次安装默认登记开机静默启动，通过 `--background` 仅驻留托盘；后续由设置 → 常规中的开关管理。程序日常启动不会登记或恢复启动项，升级安装保留关闭状态。设置开关读取 Windows 实际登记状态。默认 `Alt + N` 新建，`Alt + J` 打开列表；快捷键冲突时需选择其他组合。程序不生成演示便签，也不提供演示模式。

安装和卸载保留 AppData 中的便签数据。卸载保留语音模型，以免误删手动放入的资源。当前分发形式为 ZIP 加安装脚本，尚未生成签名的单文件 Setup.exe。

## 账号

按[自建同步服务器](../README.md#自建同步服务器)搭建同步服务。在「设置 → 账号与同步 → 登录账号」中填写服务器网址或 IP，再输入账号密码。
账号在 Casdoor 服务器管理，不将密码写入源代码或打包产物。

开发目录中直接安装当前编译版本（先自行退出已运行的索笺）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\install.ps1" -ApplicationPath ".\target\release\suojian.exe"
```

仅修复默认安装目录的应用列表登记和开始菜单入口，可运行同一脚本并加 `-RepairRegistration`；此模式不替换程序，也不修改开机启动选择。直接运行编译产物不会登记安装列表。全局快捷键需要索笺进程保持运行；注册冲突会打开设置提示修改，单个冲突不会停用另一组快捷键。
